# Профиль kiserufetch: досье с ежедневной уликой

Дата: 2026-10-06 · Статус: на ревью · Ветка: `dossier-profile`

## Цель

README профиля состоит из одной SVG-картинки: засекреченное досье, к которому каждый день подшивают новый снимок-улику. Профиль ничего не рассказывает о владельце, кроме объёма скрытой работы. Картинку раз в сутки перерисовывает GitHub Action.

Критерии готовности:

- В README только досье. В светлой и тёмной теме GitHub оно выглядит одинаково.
- Живые поля совпадают с ручным подсчётом по правилам из раздела «Правила подсчёта».
- В публичных местах (SVG, README, код, логи Actions) нет адресов почты, названий приватных репозиториев и секретов.
- Сбой не публикует нули и не портит текущую картинку.

## Вне рамок

- Варианты B и C и остальные идеи из брейншторма.
- Репозитории организаций. В 2026 году в них нет коммитов владельца.
- Коммиты вне основной ветки.
- Переписывание истории git. В старых коммитах этого репозитория видны имя и рабочая почта. Новые коммиты уже подписываются адресом `…@users.noreply.github.com`, история остаётся как есть, пока владелец не решит иначе.

## Что видит гость

Бумажная карточка с шапкой `PERSONNEL FILE` / `NO. KF-0001`. Слева поля, справа снимок-«полароид» со скрепкой, повёрнутый на 2,2°. Поверх полей стоит штамп `PRIVATE`. Внешний вид соответствует макету A из артефакта «Досье × Экспонат».

| Поле | Значение | Источник |
|---|---|---|
| SUBJECT | `kiserufetch` | константа |
| ALIAS | `Kiseru` | константа |
| OCCUPATION | `██████ developer` | константа |
| LOCATION | `███████████` | константа |
| ACTIVE SINCE | `2018` | константа |
| REPOSITORIES | `{public} public · {private} private` | живое |
| COMMITS, {Y} | `{total} · visible to you: {visible}` | живое |
| ASSOCIATES | `claude · {claude} of the above` | живое |
| LAST 24H | `{n} event(s) · contents classified` или `no activity · still life` | живое |
| NOTES | `"Hello stranger."` и две строки чёрных полос | константа |

Подпись под снимком: `EXHIBIT Nº {номер дня в году} · specimen in motion` (или `· still life`), вторая строка `recovered {DD.MM.YYYY} · seed {0xXXXX}`.
Подвал: `exhibit replaced daily at 00:00 UTC · previous exhibits destroyed`.

Числа пишутся с обычным пробелом между разрядами: `2 033`. Множественное число английское: `1 event`, `2 events`.

README целиком:

```html
<div align="center">
  <img src="assets/dossier.svg?v=YYYY-MM-DD" width="100%" alt="Personnel file. Classified.">
</div>
```

`assets/hello.gif` удаляется, в истории git он остаётся.

## Правила подсчёта

Обозначения: D — дата запуска по UTC, «вчера» — сутки D−1 с 00:00:00 до 23:59:59 UTC, Y — год даты D.

**Репозитории.** Все репозитории на аккаунте (`GET /user/repos?affiliation=owner`), включая форки и архивные. `public` и `private` считаются по флагу `private`.

**Коммиты.** Для каждого репозитория берутся коммиты основной ветки, у которых дата автора попадает в окно с `min(Y-01-01, вчера) 00:00:00Z`. Окно начинается со «вчера», если оно раньше 1 января: так 1 января строка LAST 24H видит коммиты 31 декабря. Параметр `since` в API служит только предварительным фильтром, окончательно фильтр применяется по дате автора в коде.

**Авторство.** Коммит засчитывается, если выполнено одно из условий:
- он принадлежит владельцу: `author.login == "kiserufetch"` или `commit.author.email` входит в список из секрета `DOSSIER_EMAILS` (без учёта регистра);
- он принадлежит Claude: `commit.author.email == "noreply@anthropic.com"`.

Остальные авторы (боты, другие люди) не считаются. Трейлеры `Co-Authored-By` не учитываются, у коммита ровно один автор.

**Форки.** Считаются только коммиты, которых нет в основной ветке родителя. Их список отдаёт compare API: `GET /repos/{parent}/compare/{parent_default}...{owner}:{fork_default}` (с пагинацией), к нему применяется правило авторства. Проверять `GET /repos/{parent}/commits/{sha}` нельзя: из-за общей сети форков этот запрос отвечает 200 и на коммиты, которые есть только в форке (проверено 2026-10-06).

**Итоги** (структура `Stats`):
- `public_repos`, `private_repos` — число репозиториев.
- `total` — уникальные по SHA засчитанные коммиты с датой автора в году Y во всех репозиториях.
- `visible` — те из `total`, что есть хотя бы в одном публичном репозитории.
- `claude` — те из `total`, что принадлежат Claude.
- `last24` — уникальные по SHA засчитанные коммиты с датой автора во «вчера», в том числе 31 декабря при запуске 1 января.

**Пропуск репозиториев.** Ответы 404, 409 (пустой репозиторий), 451 и 403 с уведомлением GitHub о блокировке (`block` в теле ответа) для конкретного репозитория означают пропуск. Любой другой 403 (вторичный лимит запросов, токен без доступа к содержимому) и любая другая ошибка останавливают запуск, иначе в профиль ушли бы заниженные числа.

Ориентир для проверки на 2026-10-06, ручной подсчёт без дедупликации по SHA: репозитории 15 / 11, `total` 2 033, `visible` 115, `claude` 300, активных дней 87 из 166.

## Снимок

- **Сид.** `sha256(D.isoformat() + DOSSIER_SALT)`, первые 4 байта идут в собственный PRNG (mulberry32). Модуль `random` не используется, чтобы результат не зависел от версии Python. В подписи показываются младшие 16 бит: `0x5E1F`.
- **Поле.** 30×24 клетки, края замкнуты в тор.
- **Если `last24 > 0`, получается живая колония.** Случайный «суп» с плотностью `0.16 + min(last24 / 4, 8) · 0.03`, 16 поколений прогрева, затем 60 поколений в кадр. Если к концу осталось меньше 10 живых клеток, суп пересеивается тем же PRNG, не больше 5 попыток.
- **Если `last24 == 0`, получается натюрморт.** До 10 фигур из набора block, beehive, loaf, boat, tub, pond, ship со случайным отражением и транспонированием. Между рамками фигур не меньше двух пустых клеток, от края поля не меньше одной. Главное свойство: шаг «Жизни» не меняет поле.
- **След.** Клетки, умершие на прошлом шаге, рисуются с прозрачностью 35%.

## SVG

- Ширина 880, высота по содержимому. Палитра макета: бумага `#e3e4e0`, чернила `#1b1a18`, штамп `#b3261e`, полосы `#141414`, фон снимка `#121214`, клетки `#ebe8e1`.
- Шрифт Courier Prime (Regular и Bold), урезанный до латиницы и символов `· Nº`, встроен в `<style>` как base64 WOFF2. Урезка делается один раз локально через fonttools. Результат и `OFL.txt` лежат в `dossier/font/`. В Action fonttools не нужен.
- Каждое поколение — отдельный `<path>` из клеток. Кадры по очереди показывает CSS-анимация с шагом 150 мс, цикл 9 с. При `prefers-reduced-motion: reduce` виден только первый кадр. У натюрморта один кадр и нет анимации.
- Нет скриптов и внешних ссылок. Все подставляемые строки экранируются для XML.
- Размер не больше 300 КБ.

## Запуск

`.github/workflows/dossier.yml`:

- Триггеры: `schedule: '5 0 * * *'` и `workflow_dispatch`.
- `permissions: contents: write` и `concurrency: dossier`.
- Шаги: checkout, `actions/setup-python` с Python 3.12, `python -m dossier`. Если файлы изменились, коммит от `github-actions[bot]` с сообщением `chore(dossier): exhibit YYYY-MM-DD` и push.
- Секреты:
  - `DOSSIER_TOKEN` — fine-grained токен, доступ ко всем репозиториям аккаунта, права Metadata: read и Contents: read.
  - `DOSSIER_EMAILS` — адреса через запятую.
  - `DOSSIER_SALT` — случайная строка.
- Логи публичны, поэтому в них печатаются только итоговые числа. В сообщениях об ошибках вместо названия репозитория стоит его порядковый номер в списке.
- Ежедневные коммиты бота поддерживают активность репозитория. Если GitHub всё же отключит расписание после 60 дней, его можно включить вручную во вкладке Actions.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Нет секрета, токен истёк или отозван (401) | Запуск падает до записи файлов. GitHub присылает владельцу письмо. В профиле остаётся вчерашнее досье. |
| Лимит запросов, 5xx, сетевая ошибка | Три повтора с паузой, потом падение без записи. |
| Репозиторий отвечает 404, 409, 451 или 403 с уведомлением о блокировке | Репозиторий пропускается, в лог пишется номер и код. |
| Вторичный лимит (403 с `retry-after` или сообщением о лимите) | Повторы с паузой не меньше `retry-after` (до 120 с), потом падение без записи. |
| Файл получился больше 300 КБ | Падение без записи. |

Файлы записываются только после успешного подсчёта и рендера, во временный файл с последующим переименованием.

## Тесты

Только `unittest`, внешние вызовы подменяются: функция `collect` получает клиент API параметром.

- `test_life`: натюрморт не меняется за шаг для 100 разных сидов. Один сид всегда даёт одни и те же кадры. Работает порог пересева.
- `test_collect`:
  - авторство по логину, по почте без учёта регистра, коммиты Claude, чужие авторы;
  - границы суток и года по UTC (`23:59:59` против `00:00:00`), запуск 1 января: `total` 0, а `last24` видит 31 декабря;
  - форк, где учитываются только коммиты из compare;
  - дедупликация по SHA и правило `visible`;
  - пропуск по 404, 409, 451 и заблокированному 403, падение на любом другом 403 и прочих кодах.
- `test_render`:
  - корректный XML (`xml.etree`), числа отформатированы;
  - у натюрморта нет анимации;
  - размер не больше 300 КБ;
  - в SVG нет адресов почты, названий репозиториев и `http`-ссылок.
- `test_readme`: параметр `?v=` заменяется, повторный запуск ничего не меняет.
- Вручную: локальный запуск с настоящими секретами, просмотр SVG в Chrome и Firefox. Затем один `workflow_dispatch` и проверка профиля в обеих темах.
